# DealerBRAIN engineering rules

Team Stock Overflow — non-negotiable rules.

1. Business facts must come from deterministic Python/SQL tools, not from the LLM.
2. The LLM must never invent inventory, price, dealer status, shipment status, claim status, warranty status, ETA, or transaction IDs.
3. Business calculations must be deterministic and testable.
4. Write/update/delete actions require explicit user confirmation.
5. Suspended dealers cannot create new business transactions.
6. Every recommendation must expose the evidence used.
7. Secrets must only come from environment variables.
8. Real API keys must never be committed.
9. Keep dependencies minimal.
10. Prefer readable Python over framework-heavy abstractions.
11. Do not introduce new frameworks without explicit approval.
12. Preserve working functionality during later changes.
13. Data-access code must be replaceable later by real ERP/CRM/DMS adapters.
14. LLM/orchestration code must be isolated from business-rule code.
15. Database write logic must be isolated from read/query logic.
16. Transaction IDs must be generated by deterministic application code, never by the LLM.
17. Externally visible business decisions must be auditable.
18. Deterministic business logic requires automated tests.
19. Source data is treated as read-only unless explicitly stated otherwise.
20. New features must follow the smallest-change principle.

## Architecture

```text
User
  ↓
Streamlit UI
  ↓
Application / Orchestrator
  ↓
Safe Business Tools
  ↓
Rules / Guardrails
  ↓
Repository / Data Access
  ↓
DuckDB / SQLite
```

The LLM is an orchestration and explanation layer.
It is not the system of record.
